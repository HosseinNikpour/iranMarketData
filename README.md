# Iran Market Analyzer

## راه‌اندازی محلی

```powershell
npm install
npx prisma generate
npx prisma db push
npm run dev
```

## متغیرهای محیطی

در فایل `.env` و در Vercel → Settings → Environment Variables تنظیم شوند:

```env
DATABASE_URL="postgresql://..."
DIRECT_URL="postgresql://..."
SYNC_ADMIN_KEY="یک-کلید-طولانی-و-تصادفی"
CRON_SECRET="یک-کلید-طولانی-و-متفاوت"
TSETMC_REQUEST_DELAY_MS="900"
```

`SYNC_ADMIN_KEY` برای استفاده از دکمه‌های صفحه مدیریت داده لازم است. همین مقدار را در فیلد کلید صفحه وارد کنید. `CRON_SECRET` برای محافظت از Cronهای ورسل است. هر دو کلید را محرمانه نگه دارید.

## همگام‌سازی تحت وب

صفحه `/data` شامل این عملیات است:

- به‌روزرسانی فهرست نمادها
- شروع دریافت اولیه تاریخچه قیمت
- به‌روزرسانی دستی افزایشی
- مشاهده پیشرفت و ادامه مرحله‌ای Job

هر Job در جدول `SyncRun` ذخیره می‌شود. هر درخواست فقط تعداد محدودی نماد را پردازش می‌کند تا از timeout شدن یک درخواست طولانی جلوگیری شود.

### رفتار دریافت اولیه

نمادهایی که `priceSyncStatus` آن‌ها `SUCCESS` است از دریافت اولیه مجدد کنار گذاشته می‌شوند. نمادهای باقی‌مانده پردازش می‌شوند. اگر یک نماد خطا بدهد، Job با وضعیت `PARTIAL` پایان می‌یابد و با شروع مجدد دریافت اولیه، نمادهای ناموفق دوباره بررسی می‌شوند.

### رفتار به‌روزرسانی افزایشی

برای هر نماد آخرین تاریخ ثبت‌شده در دیتابیس پیدا می‌شود. داده‌های جدید ذخیره می‌شوند و بازه سه‌روزه اخیر نیز مجدداً upsert می‌شود تا اصلاحات احتمالی TSETMC اعمال شود.

توجه: endpoint فعلی TSETMC کل تاریخچه را برمی‌گرداند؛ بنابراین این روش تعداد رکوردهای ذخیره/به‌روزرسانی‌شده را محدود می‌کند، اما هنوز حجم پاسخ شبکه‌ای TSETMC به اندازه تاریخچه کامل است.

## زمان‌بندی روزانه در Vercel Hobby

در `vercel.json` فقط یک Cron روزانه تعریف شده است:

- مسیر `/api/cron/daily` هر روز ساعت 14:00 UTC (17:30 به وقت ایران) اجرا می‌شود و Job افزایشی را ایجاد می‌کند؛ اگر Job دیگری در حال اجرا باشد، همان Job فعال را برمی‌گرداند.
- پردازش مرحله‌ای Job توسط GitHub Actions انجام می‌شود تا محدودیت Cron روزانه Vercel باعث توقف پس از یک batch نشود. فایل Workflow در `.github/workflows/daily-sync-worker.yml` هر روز ساعت 14:05 UTC اجرا می‌شود و تا پایان Job یا رسیدن به سقف زمان اجرای روزانه، Worker را فراخوانی می‌کند.
- Workflow علاوه بر زمان‌بندی روزانه، از `workflow_dispatch` نیز پشتیبانی می‌کند؛ بنابراین می‌توانی از تب Actions در GitHub آن را دستی اجرا کنی.
- اگر دریافت اولیه تاریخچه بیشتر از زمان مجاز یک اجرای GitHub Actions طول بکشد، Job در دیتابیس باقی می‌ماند و اجرای روز بعد از همان cursor ادامه می‌دهد.

در GitHub → Settings → Secrets and variables → Actions این دو Repository Secret را اضافه کن:

- `VERCEL_APP_URL`: آدرس کامل سایت، مانند `https://your-project.vercel.app` (بدون اسلش انتهایی)
- `CRON_SECRET`: دقیقاً همان مقدار تعریف‌شده در Environment Variables ورسل

در Vercel → Settings → Environment Variables نیز `CRON_SECRET` را تعریف کن. زمان‌بندی Vercel بر اساس UTC است.

**توجه:** زمان 14:00 UTC معادل 17:30 ایران است. زمان‌بندی GitHub Actions ممکن است چند دقیقه با تأخیر شروع شود. برای اجرای Worker روزانه، GitHub Actions باید فعال باشد و Repository Secretهای بالا تنظیم شده باشند.

## استقرار

1. Push کد به GitHub.
2. در Vercel پروژه را Import کنید.
3. متغیرهای محیطی بالا را تنظیم کنید.
4. در اولین Deploy پس از تغییر Schema، یک‌بار این دستور را در محیط توسعه اجرا کنید و تغییرات را commit کنید:

```powershell
npx prisma db push
```

5. Deploy کنید.
6. در GitHub، دو Repository Secret با نام‌های `VERCEL_APP_URL` و `CRON_SECRET` بسازید.
7. وارد `/data` شوید، کلید `SYNC_ADMIN_KEY` را وارد کنید و «به‌روزرسانی فهرست نمادها» را بزنید.
8. «شروع دریافت اولیه تاریخچه» را اجرا کنید؛ سپس از GitHub → Actions → Daily price sync worker گزینه Run workflow را بزنید تا پردازش از همان Job شروع شود. پس از آن Worker طبق برنامه روزانه ادامه می‌دهد.

## اجرای Worker محلی

دستورهای CLI قبلی حفظ شده‌اند. برای اجرای کامل از ترمینال همچنان از گزینه `--all` مطابق CLI استفاده کنید.
